# ADR-0001 — WebRTC с публичным signaling без домашнего сервера

Статус: Accepted
Дата: 2026-07-29
Решение владельца: «хочу WebRTC и сигналлинг… если на сервер Студии, то ок».

## Контекст

Браузер не может слушать UDP discovery Дудки и не может автоматически
согласовать WebRTC с другой вкладкой без внешнего rendezvous. Пользователь не
хочет ставить или обслуживать домашний сервер.

## Решение

- Статика: `https://zamoo.team/dudka/web/`.
- Signaling: `wss://zamoo.team/dudka/signal`.
- Сервер Студии группирует живые вкладки по видимому ему публичному IPv4.
- Группа существует только в памяти, пока открыт хотя бы один WebSocket.
- Сервер маршрутизирует только WebRTC offer/answer/ICE по случайным ID вкладок.
- `RTCPeerConnection` использует собственный `stun:zamoo.team:3478`. STUN
  сообщает браузеру наблюдаемый UDP-адрес, но не принимает и не пересылает
  сообщения или файлы.
- TURN отсутствует, поэтому сервер Студии не становится data relay.
- Текст и файлы идут по зашифрованным DTLS DataChannel.
- До явного согласия пользователя signaling и WebRTC не запускаются.

## Почему не другие варианты

- Ручной QR/код решает signaling, но нарушает требование автоматического поиска.
- Постоянный домашний `dudkad-web` надёжен, но пользователь явно отказался
  обслуживать сервер.
- Сторонний STUN раскрывает сетевой адрес ещё одному оператору. Собственный
  STUN Студии оставляет этот узкий контур в уже разрешённой инфраструктуре.
- TURN повысил бы связность сильнее, но превратил бы сервер в канал передачи
  сообщений и файлов. Этот выпуск его не использует.
- Один глобальный signaling-room раскрывает участников и создаёт
  неконтролируемый O(n²); группировка по внешнему IPv4 с лимитом 8 уже и
  соответствует обычной квартире.

## Последствия

- Signaling становится узкой WAN-зависимостью только для браузерной версии.
- Один внешний IP не доказывает доверие: CGNAT может объединить чужие вкладки.
  Отсутствие TURN не даёт им готового WAN-реле, но это не аутентификация.
  Экран согласия сообщает про signaling и STUN до первого запроса.
- При недоступном signaling новые вкладки не знакомятся; уже открытый WebRTC
  DataChannel продолжает работать.
- Фоновая вкладка может быть заморожена браузером; push и гарантированная
  доставка не обещаются.
