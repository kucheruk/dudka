# ADR-0002 — Один WebRTC mesh для браузеров и приложений

Статус: Accepted
Дата: 2026-07-29
Решение владельца: «оставим только вариант как браузеры общаются».

## Контекст

Браузерные клиенты использовали WebRTC, а нативные приложения — отдельный
UDP/TCP discovery и LAN-протокол. Поэтому две группы не видели участников,
сообщения и файлы друг друга.

## Решение

- Браузеры, desktop-приложения и Linux TUI используют один signaling,
  один STUN и совместимые WebRTC DataChannel-пакеты.
- `dudkad` больше не поднимает UDP broadcast и TCP session `41777`.
- Сервер Студии по-прежнему передаёт только `offer`, `answer` и ICE.
- Текст, хвост истории и файлы идут напрямую по DTLS DataChannel.
- До первого WAN-соединения нативный клиент показывает такое же понятное
  объяснение и требует явного согласия.
- Кнопка «ИСКАТЬ» переподключает signaling; сканирования подсети больше нет.

## Последствия

- Браузер и приложение становятся равноправными участниками одного mesh.
- Новое знакомство зависит от доступности signaling Студии; готовый прямой
  канал продолжает работать без signaling.
- TURN по-прежнему отсутствует. При несовместимых NAT прямой канал может не
  подняться, но сообщения и файлы не переходят через сервер.
- Это несовместимая замена сетевого протокола и требует major-версии.
