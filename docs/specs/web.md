# DUD-WEB — Браузерная Дудка

Статус документа: Accepted
Владелец: ДУДКА
Последнее смысловое изменение: 2026-07-29

## Назначение и границы

Две или несколько вкладок современного браузера в одной домашней LAN находят
друг друга через узкий сигнальный сервис Студии, после чего обмениваются
сообщениями и файлами напрямую по WebRTC DataChannel. Пользователю не нужен
домашний сервер, установленное приложение, аккаунт, комната или код.

### Non-goals

- передача или хранение сообщений и файлов сигнальным сервисом;
- TURN-реле, STUN, облачная история, push и работа вкладки в фоне;
- доказательство принадлежности одной семье только по внешнему IP;
- скрытый запуск signaling до явного согласия пользователя.

## Требования

### DUD-WEB-101

Priority: P0
Status: Accepted

До первого signaling-запроса веб-Дудка показывает отдельный блокирующий экран
информированного согласия на упрощённом техническом русском языке.

Экран сообщает:

- кто выходит в интернет: текущая вкладка;
- куда: сигнальный сервис Студии на `zamoo.team`;
- зачем: найти другие вкладки Дудки с того же домашнего подключения и передать
  служебные WebRTC offer/answer/ICE;
- какие данные видит сервис: публичный IP, случайный ID вкладки, User-Agent в
  обычном HTTP-запросе и служебные WebRTC-описания;
- какие данные сервис не получает: имя пользователя, сообщения, файлы и
  история;
- объём и срок: один WebSocket, пакеты не более 64 КиБ, только пока вкладка
  открыта; состояние соединения удаляется сразу после отключения;
- что содержимое после соединения идёт напрямую между браузерами по WebRTC
  DTLS; STUN и TURN не используются.

Проверка:

- до кнопки `РАЗРЕШИТЬ И НАЙТИ СВОИХ` нет WebSocket, WebRTC и запросов к
  `/dudka/signal`;
- кнопка `ОСТАТЬСЯ ОФЛАЙН` оставляет экран согласия и не запускает сеть;
- согласие запрашивается заново для каждой вкладки и не считается данным по
  умолчанию;
- evidence: браузерный автотест сети до/после согласия.

Зависимости: DUD-NET-160
ADR: `docs/adr/0001-browser-webrtc-signaling.md`

### DUD-WEB-110

Priority: P0
Status: Accepted

Сигнальный сервис автоматически объединяет одновременно открытые вкладки по
публичному IPv4 источника запроса. Он держит только живые WebSocket-соединения
в памяти и маршрутизирует разрешённые сообщения `offer`, `answer`, `ice`.

Проверка:

- вкладки с одного внешнего IPv4 видят друг друга без комнаты или кода;
- вкладки из разных групп не получают ID и signaling друг друга;
- после закрытия последнего WebSocket группа отсутствует в памяти;
- сервис не пишет IP, SDP, ICE, имена или содержимое пакетов в приложение-лог;
- не более 8 вкладок в группе, 64 КиБ на signaling-пакет и 20 пакетов/с на
  соединение;
- evidence: unit/integration tests сигнального hub.

Зависимости: DUD-WEB-101
ADR: `docs/adr/0001-browser-webrtc-signaling.md`

### DUD-WEB-120

Priority: P0
Status: Accepted

После signaling вкладки строят полносвязную WebRTC-сеть без `iceServers`.
Основной DataChannel надёжен и упорядочен. Текст, имя и синхронизация хвоста
идут только через него; сервер signaling не является участником чата.

Проверка:

- две вкладки одного браузера через изолированные browser contexts соединяются
  и показывают `онлайн 2`;
- сообщение появляется во второй вкладке, первая вкладка не получает ложного
  подтверждения доставки;
- последние 200 текстовых сообщений хранятся только в localStorage браузера и
  сливаются по ID при соединении;
- закрытие signaling после установленного WebRTC не разрывает готовый чат;
- evidence: браузерный E2E двух contexts.

Зависимости: DUD-WEB-110
ADR: `docs/adr/0001-browser-webrtc-signaling.md`

### DUD-WEB-130

Priority: P1
Status: Accepted

Веб-Дудка отправляет один или несколько выбранных файлов только после нажатия
кнопки самолётика. До отправки видны имя, размер, thumbnail изображения и
действие удаления. Комментарий отправляется вместе с батчем.

Проверка:

- выбор файла не начинает WebRTC-передачу;
- получатель видит исходное имя и расширение, размер и thumbnail для
  `image/*`, включая GIF;
- загрузка создаёт Blob URL только в браузере получателя, ссылка содержит
  исходный `download` filename;
- большие файлы передаются чанками 16 КиБ с backpressure; файлы и Blob URL не
  пишутся в signaling и localStorage;
- evidence: браузерный E2E текста + малого файла.

Зависимости: DUD-WEB-120
ADR: `docs/adr/0001-browser-webrtc-signaling.md`

### DUD-WEB-140

Priority: P0
Status: Accepted

Веб-интерфейс и WebSocket имеют один HTTPS origin `zamoo.team`. Сигнальный
сервис принимает `Origin: https://zamoo.team`, не принимает чат-сообщения и
файлы, не поддерживает wildcard CORS и не доверяет клиентскому room ID.

Проверка:

- чужой Origin получает отказ до WebSocket upgrade;
- неизвестный тип, неверный target, превышение лимита и попытка пересылки
  `chat`/`file` закрывают или отвергают запрос;
- readiness не раскрывает группы и участников;
- evidence: негативные HTTP/WebSocket tests.

Зависимости: DUD-WEB-110
ADR: `docs/adr/0001-browser-webrtc-signaling.md`
