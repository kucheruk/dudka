# DUD-AGT — Домашние агенты (MCP на LAN)

Статус документа: Accepted · 2026-07-28  
Владелец: ДУДКА  
Последнее смысловое изменение: 2026-07-28

## Назначение и границы

ДУДКА умеет выступать **MCP-клиентом** к домашним агентам в той же квартирной LAN. Агент появляется в общем чате как peer с читаемым префиксом в display name; человек — без префикса. Тот же no-WAN контур, что и у людей (`DUD-NET-*`).

Это **не** интеграция с «Диалогами» / «Доверием» и не cloud MCP.

### Non-goals

- Облачный MCP / публичный интернет к агентам.
- Identity/RBAC через Доверие.
- Полная MCP-surface всех студийных продуктов — только home-agent tools, нужные чату (текст in/out; файлы — позже по отдельным ID).
- Обязательная регистрация агента у человека.

## Требования

### DUD-AGT-101

Priority: P1  
Status: Accepted

Engine/клиент Дудки может выступать MCP-клиентом к агенту, достижимому только в link-local / loopback / RFC1918 (тот же контур, что `DUD-NET-101`). Исходящий WAN к MCP запрещён.

Проверка:

- попытка MCP URL вне LAN отвергается / не инициируется;
- evidence: unit/integration + WAN-refuse тест (после реализации).

Зависимости: DUD-NET-101  
ADR: не требуется (пока)

### DUD-AGT-110

Priority: P1  
Status: Accepted

Агент в чате всегда имеет **тройной префикс** в `display_name` / нике. Канонический формат из трёх частей:

```text
{agent_name}·{model_id}·{host_id}
```

Примеры: `Codex·gpt-5·mac-mini`, `Claude·sonnet·nas`. Разделитель — middle dot `·` (U+00B7) между всеми тремя частями.  
- `agent_name` — короткое имя рантайма/роли (без `·` и пробелов; допустимы `-`, `_`);  
- `model_id` — краткий id модели (без `·` и пробелов; допустимы `-`, `_`, `.`);  
- `host_id` — короткое имя машины/хоста в квартире (без `·` и пробелов; допустимы `-`, `_`).  

Ровно **две** точки `·` (три непустых сегмента). Человек **никогда** не получает такой префикс автоматически; агент **не может** представиться без полного тройного префикса (reject / нормализация).

Проверка:

- сообщение от агента в ленте содержит тройной префикс (`a·b·c`); сообщение человека — без обязательных двух `·`;
- ник агента с 0/1/3+ разделителями `·` или пустым сегментом → ошибка или авто-нормализация по правилам спеки;
- evidence: unit на форматтер + smoke двух процессов (после P11x).

Зависимости: DUD-CHAT-110  
ADR: не требуется

### DUD-AGT-120

Priority: P1  
Status: Accepted

Агент обнаруживается/анонсируется в той же LAN discovery-грамматике квартиры (не mDNS-as-only). Минимум: peer виден в списке соседей с agent-маркером и префиксным ником.

Проверка:

- два процесса (человек + agent stub) на loopback/LAN видят друг друга в peers;
- evidence: smoke script (после реализации).

Зависимости: DUD-NET-110, DUD-AGT-110  
ADR: может понадобиться, если advertise уйдёт в отдельный порт/протокол

### DUD-AGT-130

Priority: P1  
Status: Draft

Через MCP tool agent может **отправить** текст в общий чат и **получить** входящий текст (подписка/poll — деталь реализации). Паритет смысла с человеческим `POST /send` / лентой: best-effort, без ложного «доставлено всем».

Проверка:

- agent → человек: текст в ленте GUI/TUI;
- человек → agent: agent получает текст через MCP;
- evidence: smoke двумя процессами (после реализации).

Зависимости: DUD-CHAT-101, DUD-AGT-101  
ADR: не требуется
