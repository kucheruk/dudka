# AGENTS.md — ДУДКА

> Конституция репозитория. Кода пока нет; первая реализация обязана сразу заложить правила ниже.
> Корневые правила студии: [`../AGENTS.md`](../AGENTS.md).

## Что это за продукт

«ДУДКА» — **примитивное** приложение: один общий LAN-чат квартиры, текст и файлы, без аккаунтов и без облака.  
Не корпоративный мессенджер. Не платформа. Сложность — враг; лучше короткая дыра в UX, чем второй слой абстракций.

## Бэклог и доски

Разработка ведётся **без доски в «Делах»**.  
Единственный источник задач и порядка — [`ROADMAP.md`](ROADMAP.md) (чеклист `P001`…; после MVP — в т.ч. `P110+` агенты).  
Не заводи карточки в Делах «для Дудки», не жди space/board. Закрыл пункт — отметь `[x]` в ROADMAP в том же коммите.  
Спеки `DUD-*` задают контракт приёмки; ROADMAP — нарезку работы.

## Границы продукта

Владеет: локальный discovery, peer-сессия, общий чат, хвост истории, передача файлов **только в LAN**.  
Не владеет: identity/RBAC (`Доверие` в MVP нет), облако, push через интернет, интеграции с «Диалогами».  
После MVP реализован локальный stdio MCP server для домашних агентов в той же
LAN — чеклист фазы 7 в [`ROADMAP.md`](ROADMAP.md), контракт
[`docs/specs/agents.md`](docs/specs/agents.md); ник агента всегда
`{агент}·{модель}·{хост}`.

## Регуляторный контур

Исходящий интернет в рантайме запрещён, кроме узкого пользовательского контура
автообновления ([`docs/specs/network.md`](docs/specs/network.md),
[`docs/specs/updates.md`](docs/specs/updates.md)). Manifest читается только с
`zamoo.team`, никакой telemetry/callhome вместе с запросом не отправляется.

## Базовый стек первой реализации

- Go: engine (`dudkad`), протокол, discovery, файлы, дополнительный TUI.
- Flutter: iOS / Android / Windows / macOS / Linux UI по
  [`DESIGN.md`](DESIGN.md).
- Связка Flutter↔Go: локальный loopback API engine (`127.0.0.1` / UDS); протокол не дублировать во втором языке.
- Данные: локальные файлы устройства; без внешней БД.
- Облако, mDNS-as-only-discovery, auth-провайдер — только по явной просьбе владельца / ADR.

2. Удобство UI

## Скорость — фича №1 студии

Числовые бюджеты — в [`docs/specs/product.md`](docs/specs/product.md). Бюджет не повышают ради зелёного теста.

## Инженерные инварианты

- Сначала ID `DUD-*` в спеке (если меняется контракт), потом маленькая дельта из ROADMAP, потом тест/видимый пруф.
- Бери **один** следующий незакрытый пункт с наименьшим `P***` (или явный диапазон от владельца) — не распараллеливай полфазы в одном PR без нужды.
- Каждый принимаемый SHA: ноль warnings и errors.
- Engine не инициирует соединения за пределы link-local / loopback / RFC1918 (DUD-NET-*).
- Файлы обозримые; не плодить второй UI-стек.
- Большой несвязанный рефакторинг — отдельный пункт ROADMAP, не «заодно».

## Работа агента

- Старт смены: открой [`ROADMAP.md`](ROADMAP.md), найди следующий `[ ]` с минимальным P, сделай только его (или явно согласованную микропачку соседних P).
- Перед правкой: `PRODUCT.md`, `DESIGN.md`, нужный `docs/specs/*`.
- UI: anti-goals — регистрация, облако, комнаты/коды, баннеры, сложные настройки; без CRT-фанатизма.
- Порезы тулинга — [`../papercuts/dudka.md`](../papercuts/dudka.md) или `papercuts` в этом репо, если заведёте.
- Не коммить секреты, чужие переписки, дампы сетей.

## Commit + push — обязательный финал

Каждое законченное изменение **обязательно** заканчивается `git commit` и `git push` в `origin` (ветка работы, обычно `master`).  
«Законченное» = пункт ROADMAP закрыт / видимый результат достигнут / договорённый кусок смены сделан. Не оставляй закрытую работу только в рабочем дереве.  
Если push невозможен (сеть, hook) — остановись и напиши владельцу причину; не считай задачу закрытой.

## Версии, release notes и деплой

Версия Дудки имеет вид `MAJOR.MINOR.PATCH`. Тип всего батча определяет самое
сильное изменение в нём:

- багфиксы и совместимые мелкие улучшения увеличивают последнюю цифру:
  `1.2.3 → 1.2.4`;
- новые пользовательские возможности увеличивают вторую цифру и обнуляют
  последнюю: `1.2.3 → 1.3.0`;
- радикальные или обратно несовместимые изменения увеличивают первую цифру и
  обнуляют остальные: `1.2.3 → 2.0.0`.

Каждый законченный батч изменений — это новая версия. Нельзя закрыть батч
только коммитом кода: в том же release-проходе агент обязан:

1. синхронно обновить версию в `apps/dudka/pubspec.yaml` и
   `internal/version/version.go`; Flutter build number после `+` всегда
   монотонно увеличивается;
2. добавить датированную секцию новой версии в начало [`CHANGELOG.md`](CHANGELOG.md);
   это единственный источник текста для release notes;
3. прогнать `./scripts/check.sh` и платформенные build-тесты затронутых
   артефактов;
4. влить release-коммит в `master`, поставить аннотированный тег `vX.Y.Z` на
   этот SHA и отправить `master` с тегом в канонический `origin` и публичное
   зеркало `github`;
5. собрать артефакты, опубликовать GitHub Release `vX.Y.Z` с текстом секции из
   changelog и контрольными суммами;
6. в том же батче обновить `zamoo.team/dudka/`: видимую версию, ссылки на
   артефакты, ссылку на release notes и `update.json` с точными size/SHA-256
   desktop-пакетов; закоммитить и запушить лендинг;
7. прочитать обратно тег, release assets и публичный лендинг. Только после
   этого версия считается задеплоенной.

Prerelease-суффиксы (`-alpha.N`, `-beta.N`, `-rc.N`) используются только по
явному решению владельца. Если публикация release или лендинга невозможна,
агент останавливается с конкретным блокером и не называет батч законченным.

## Concierge-рапорт по закрытой P

В каждый рапорт Concierge по Дудке обязательно:

1. **Осталось задач** — число незакрытых `[ ]` пунктов с P-номерами в [`ROADMAP.md`](ROADMAP.md); опционально «в текущей фазе: M».
2. **ETA основного корпуса** — фазы 0–5 (до конца полировки, без фазы 6 «После MVP»): темп сессии (среднее мин/P по последним закрытым) × оставшиеся P корпуса; одна строка допущений.

Пример: `Осталось: N (фаза K: M) · ETA корпуса: ~Xh / дата (темп ~Y мин/P; …)`.
