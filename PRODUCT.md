# Product

<!-- impeccable:product-schema 1 -->

## Platform

adaptive

## Users

Небольшие семьи айтишников в одной квартире (один Wi‑Fi). Устали от блокировок мессенджеров и лишней сложности, когда нужно просто переслать строку или файл рядом живущему человеку.

## Product Purpose

ДУДКА (`dudka`) — локальный чат квартиры: текст и файлы между устройствами в
одной LAN без аккаунтов и облака. Исходящий интернет закрыт, кроме публичного
desktop update manifest/artifact без telemetry. Успех: открыл приложение →
сразу в общем чате с теми, кто онлайн в том же Wi‑Fi; текст и файлы видят те,
кто онлайн (best-effort, без ложного «доставлено всем»).

## Positioning

Не корпоративный мессенджер и не облачный сервис. Отличие: жёстко LAN-only, чтобы не попадать под регуляторный ворох «мессенджера в интернете». Один общий чат на сеть (комнаты — позже, без кодов).

## Operating Context

Один SSID / одна квартирная сеть. Устройства: телефоны и компьютеры семьи.
Сценарий — «перекинуть ссылку, скрин, pdf, иногда большое видео». История —
короткий хвост у уже онлайн, не вечный архив. macOS и Windows имеют desktop
GUI; основной Linux-клиент — самостоятельный терминальный TUI.

## Capabilities and Constraints

- Платформы GUI: iOS, Android, Windows и macOS (Flutter). Linux поставляется
  как основной Go TUI; Windows TUI остаётся инструментом диагностики.
- Core/протокол: Go. Discovery: UDP broadcast + TCP register + subnet scan; не mDNS.
- Без авторизации и аутентификации. Ник: спросить → имя устройства → «Прилагательное + животное».
- Файлы без жёсткого лимита размера; прогресс и отмена; превью картинок в ленте.
- Ник, стабильный peer_id и локальный хвост 200 сообщений сохраняются вне
  приложения и переживают обновление или повторную установку поверх.
- Нативный рантайм чата без интернета: нет cloud sync, telemetry или relay.
  Desktop GUI проверяет только публичный update manifest и release artifact по
  DUD-UPD. Браузерная версия после отдельного информированного согласия
  использует signaling и STUN Студии; STUN сообщает браузеру только его
  сетевой адрес. Текст и файлы идут напрямую по WebRTC, TURN отсутствует.
- UI MVP: только русский.
- Семантика отправки: **«ОТПРАВИТЬ»** (не «дунуть» и не облачный Send);
  в compose действие показано иконкой самолётика с русским tooltip.
- Осознанно не в MVP: комнаты, голос/звонки, E2E как продукт, интеграция с Диалогами/Доверием.
- Домашние агенты подключаются к Дудке через локальный **stdio MCP server**
  `dudka-mcp`, который говорит с `dudkad` по loopback (без интернета). Доступны
  установка тройного ника `{агент}·{модель}·{хост}`, отправка текста и чтение
  ленты — см. [`docs/specs/agents.md`](docs/specs/agents.md) и фазу 7 в
  [`ROADMAP.md`](ROADMAP.md).

## Brand Commitments

- Имя: **ДУДКА** / `dudka`.
- Ощущение ошибки даже при красивом UI: обязательная регистрация, облачные намёки, «комнаты/коды», баннеры, сложные настройки.
- Визуальный steer (shape): жёстче гик/терминал; отсылка к BBS / Terminate, **без фанатизма** — не CRT/ANSI/scanline-театр.
- Выбранный мир (shape, seed `c3406aa1` r2): **early-80s rhythm machine step row** (challenger `signals-instruments-drum-machine-step-row`) — charcoal panel, quartered step colors, silkscreen labels, segmented status; фьюз с фактами Дудки и BBS-lite операционкой.

## Evidence on Hand

Пока только продуктовые договорённости из дизайн-сессии. Скриншотов, логотипа и реальных ассетов нет — не выдумывать testimonials и метрики.

## Product Principles

1. Ноль трения: открыл — уже в чате.
2. Ноль интернета для чата — это фича и юридический контур; узкий desktop
   updater не передаёт пользовательские данные.
3. Дешевизна разработки важнее изящества протокола; UI удобство — следующий приоритет; скорость — третий.
4. Честность пустых состояний: «никого рядом» без облачного fallback.
5. Сложность прятать: настройки минимальны — ник и desktop-автозапуск; комнаты
   и коды — не в MVP.
